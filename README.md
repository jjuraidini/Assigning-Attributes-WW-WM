# Assigning-Attributes-WW-WM
Script for assigning missing attributes (specifically the ASB_DATE field) for both waste water and water mains, testing was done on local copies of the authoritative feature layers. Purpose of the script is to assign missing attributes based on the snapping or proximity of the pipe or segment. 

The objective of this task is to identify and correct missing installation date attributes (ASB_DATE) on water and sanitary sewer main line features where the data loss is the result of line segmentation rather than true differences in installation history. In the current dataset, many mains that were installed as a single project are represented as multiple line segments due to editing, splitting, or data conversion processes. As a result, some segments retain a valid ASB_DATE while adjacent segments of the same physical pipe are missing that value. The goal is to safely and defensibly propagate existing ASB_DATE values to those adjacent segments so that each continuous pipe is represented consistently, without introducing assumptions across unrelated or nearby infrastructure.

To accomplish this, the work focuses on operating within each feature class independently and using spatial relationships to infer which segments belong to the same physical main. Because there is no separate reference or authoritative “source” layer, the process relies on identifying segments that directly touch at their endpoints. Segments that share endpoints are very likely to be part of the same pipe, making endpoint connectivity the most reliable proxy for pipe continuity without performing full network tracing. Only segments with a null ASB_DATE are evaluated, and values are copied only from directly connected segments that already have a populated ASB_DATE, ensuring that existing valid data is never overwritten.

The process requires careful spatial analysis steps, including separating features with and without ASB_DATE values, generating endpoint geometries for both groups, performing spatial joins to detect endpoint intersections, and then updating the original line features based on those matches. Each of these steps must be executed and validated separately for the water and sanitary sewer datasets to prevent any cross-system contamination. Additionally, tight spatial rules are intentionally used so that dates are not transferred between parallel pipes, nearby but unrelated mains, or features that merely fall within a proximity threshold but are not actually connected.

This task takes time because it is intentionally conservative and must be thoroughly tested on local copies of the authoritative data before any production updates are considered. The logic must be validated visually and statistically to confirm that only segmented portions of the same pipe are being updated. Edge cases such as dead-ends, recent replacements, complex intersections, or areas with dense infrastructure require spot-checking to ensure the assumptions hold true. Documentation, logging, and quality assurance are also important components of the process so that the methodology is transparent, repeatable, and defensible for future audits or data migrations.
